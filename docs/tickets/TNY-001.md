# TNY-001 — Repository and implementation audit

- **Status:** Proposed / not started
- **Specification:** [Implementation Specification v1](../specs/implementation-spec-v1.md)
- **Dependencies:** None

## Objective
Inspect the actual repository before choosing architecture or implementing features.

## Tasks
- Inventory tracked files, branches, commits, manifests, application entry points, API routes, migrations/schema, tests, CI, deployment config, and secret/config patterns.
- Run safe repository-supported checks and compare implementation with approved policy.
- Identify existing work that must not be overwritten.

## Acceptance criteria
- Baseline report identifies actual stack, setup/test commands, schema/migrations, deployment model, and gaps.
- Capabilities are classified as implemented and verified, partial, absent, broken, or not verifiable.
- Missing manifests/entry points and checks that could not run are explicit.
- No unrelated files are changed and no stack/schema is invented.

## Verification and deliverables
Record exact commands/outcomes, distinguish inspection from tests, and produce a policy-versus-implementation gap report with evidence-based ticket adjustments.

## Implementation guardrails
- Inspect actual code, tests, migrations, and relevant policy before editing.
- Treat this ticket as a task definition, not evidence of existing functionality.
- Keep changes scoped and follow repository engineering conventions.
- Do not invent unresolved policy values; record blockers and decision options.
